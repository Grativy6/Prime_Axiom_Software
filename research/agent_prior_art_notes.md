# Build 000 prior-art and adversarial representation notes

Date: 2026-08-24
Scope: mathematical and computing work adjacent to exact prime-exponent / valuation representations, plus the closest machine-number alternatives. This is a research note, not a novelty opinion or an exhaustive patent search. The PAL/A0 documents are not used as specifications here.

## Result in one page

The core representation is established mathematics, not a new number system. For every positive integer `n`,

```text
F(n) : prime -> exponent
F(n)(p) = v_p(n)
```

is a finitely supported map. It identifies the multiplicative monoid of positive integers with the free commutative monoid on the primes. Lean's mathlib implements essentially this exact object as `Nat.factorization : Nat -> (Nat ->₀ Nat)` and proves, for nonzero inputs, `factorization (a*b) = factorization a + factorization b`, reconstruction, injectivity, powers, and coordinatewise divisibility [S1]. Thus a sparse prime/exponent map is a sound implementation target, but it is prior art at the level of both mathematics and executable formalization.

The strongest conclusion from the surrounding literature is narrower and more useful:

1. A prime-native representation first becomes coherent **above** a substrate that already supplies stable state, finite memory, symbolic identity, and counters. It is not a credible replacement for two-state distinction or switching. An unbounded prime namespace has to be encoded in finite states.
2. It is an excellent native domain for multiplication, exact division, rational cancellation, divisibility, gcd/lcm, powers/roots, and multiplicative arithmetic functions.
3. It is a poor sole general-purpose integer domain. Ingress from ordinary magnitude is factorization; exact numeric order is global; zero and sign need extra structure; and addition generally creates a new cofactor whose prime structure is not a local function of the input coordinates.
4. Multiplication is not literally free. With unary prime tokens it is multiset concatenation but storage is large and normalization groups/sorts tokens. With exponent counters it is a sparse merge plus **ordinary addition of exponent fields**. With binary exponent bits, it is a bank of adders with per-prime carry.
5. The closest hardware precedents are logarithmic and multidimensional logarithmic number systems (multiplication becomes exponent addition), double-base systems (sums of `2^a 3^b` terms), and residue number systems (parallel number-theoretic coordinates). None is the same as a canonical full factorization machine.
6. The most promising Build 000 architecture is therefore not “replace binary integers.” It is a **typed, multi-domain arithmetic machine** with an exact factor domain, an ordinary magnitude domain, an optional finite valuation/residue sidecar, and explicit, metered crossings between them.
7. A second promising experiment is to lift a single factored value (analogous to a monomial) into a lazy sum/product expression DAG. That lets addition remain representable without immediate refactorization, but it does not make equality, comparison, or canonicalization cheap. Arithmetic-circuit complexity is the relevant warning.

I found no strong peer-reviewed evidence in this pass for a general-purpose processor that stores every arbitrary exact integer canonically as its complete prime factorization. This is a bounded literature-search result, not proof of absence.

## 1. Exact algebraic identity: what is already known

Let `P` be the set of ordinary primes and let `N^(P)` mean finitely supported maps `P -> N`. For `n > 0`, define `F(n)_p = v_p(n)`. Unique factorization gives a bijection

```text
(positive integers, multiplication, 1)  <->  (N^(P), coordinate addition, zero vector).
```

Equivalently, positive integers under multiplication are the free commutative monoid generated by the primes. Positive rationals are the group completion: finitely supported maps `P -> Z`. The exact local laws are:

| Integer/rational operation | Exponent-coordinate operation | Conditions |
|---|---|---|
| `1` | empty map | exact |
| `a*b` | `F(a)+F(b)` | `a,b != 0` |
| `a/b` | `F(a)-F(b)` | signed exponents for rationals; nonnegative result for exact integer division |
| `a^k` | `k * F(a)` | ordinary exponent scalar `k` remains an integer |
| `a divides b` | `F(a) <= F(b)` coordinatewise | nonzero positive integers |
| `gcd(a,b)` | coordinatewise `min` | exact |
| `lcm(a,b)` | coordinatewise `max` | exact |
| perfect `k`th power | every exponent divisible by `k` | exact |
| positive numeric size | `log a = sum_p F(a)_p log p` | a global weighted reduction |

Mathlib is especially useful prior art because it exposes the engineering boundary cleanly. It represents a factorization as a finite-support function, proves multiplication-to-addition and reconstruction, and restricts injectivity to nonzero naturals [S1]. Its convention `factorization 0 = 0` means zero and one both have an empty factor map; a machine that needs semantic injectivity must use an explicit zero tag.

### Zero, sign, and rationals are not cosmetic details

- `1` is the empty factor multiset.
- `0` is an absorbing element under multiplication and has `v_p(0)=+infinity` for every prime under the extended valuation convention. That is not a finite-support vector. Use a separate zero tag.
- The units of the ordinary integers are `+1` and `-1`. Exact signed integers need a sign/unit component in addition to the prime vector.
- Positive rationals fit more naturally than signed integers: allow signed exponent coordinates. Division and cancellation then become local. Zero remains separate.
- Signed addition may cancel to zero, so even a sign bit plus exponent vector is not closed under a purely local sign rule.

### Addition is constrained, but not completely structureless

Valuation theory gives [S2]:

```text
v_p(a*b) = v_p(a) + v_p(b)
v_p(a+b) >= min(v_p(a), v_p(b))
```

When `v_p(a) != v_p(b)`, equality holds in the second line. When the valuations are equal, cancellation in the unit parts can raise the output valuation and residue information is needed to know by how much. Operationally:

```text
g = gcd(a,b)
a+b = g * (a/g + b/g)
```

so the coordinatewise minimum is a factor that addition can preserve without reconstructing everything. The residual sum is the disruptive part. This supports an `ADD_SPLIT` experiment that returns a known factor vector plus an opaque or magnitude-domain cofactor; it does not support a claim that full factorized addition is local.

### A structural impossibility result for a multiplication-only foundation

Ordinary addition cannot be recovered from the **abstract** free commutative monoid alone. Any permutation of prime generators extends to a monoid automorphism. Ordinary addition is not invariant under those automorphisms. For example, let an automorphism swap prime generators `2` and `3`. It maps `4=2^2` to `9=3^2`, but mapping the operands of `2+2=4` and then adding gives `3+3=6`, not `9`.

Therefore multiplication plus anonymous prime atoms does not determine the ordinary additive structure. A system must add at least one of:

- conventional prime values/magnitudes;
- an order or successor relation that pins those values down;
- an explicit evaluation map from prime identities to ordinary integers;
- or an independently specified addition table/algorithm.

Calling primes by their increasing indices already imports ordinary magnitude order. An arbitrary enumeration would still support a free commutative monoid, but would not recover conventional addition.

## 2. Closest prior art, ranked by actual proximity

### 2.1 Exact factor maps and valuation vectors — identical mathematical representation

This is the direct prior art. In number theory, `v_p(n)` is the multiplicity of `p`; in formal libraries, factorization is a finite-support function; in commutative algebra, unique factorization is expressed through free commutative monoids. Mathlib's implementation and the Stacks Project's valuation laws are stable, inspectable references [S1, S2].

What is not supplied by this prior art is a general-purpose physical instruction set or evidence that the representation wins on mixed workloads. That is where Build 000 can contribute experimentally.

### 2.2 Monomial exponent vectors and sparse computer algebra — computationally almost identical

A monomial `x_1^e1 ... x_k^ek` is represented by its exponent vector; monomial multiplication adds those vectors, while divisibility and lcm are coordinatewise. Sparse polynomial systems pack exponent fields and exploit machine-word addition/comparison for monomial operations [S3]. Replace variable `x_i` with prime `p_i` and a factored positive integer is exactly an evaluated monomial.

This analogy suggests a principled extension for addition:

```text
single factor word       ~ one monomial
sum of factor words      ~ sparse polynomial
shared expression DAG    ~ arithmetic circuit / straight-line program
```

But there is a decisive caveat. Polynomial variables are algebraically independent; evaluated primes are not. A symbolic system that treats `x_2`, `x_3`, and `x_5` as independent will not discover the integer relation `2+3=5`. Imposing evaluation relations collapses the problem back to ordinary integer semantics. Lazy sums preserve structure and provenance, but exact equality/order may require evaluation, circuit reasoning, and perhaps factorization.

Kaltofen's work on polynomials given by straight-line programs is relevant for the general idea that factored or circuit form can remain exponentially more succinct than expansion [S4]. It is analogy, not a result about factoring ordinary integer sums.

### 2.3 Product-of-exponentials and multiplication/division circuits — very close succinct representation

Etessami, Stewart, and Yannakakis study exact integers/rationals written as products of exponentials, equivalently arithmetic circuits with multiplication and division gates [S5]. Their split is directly relevant:

- equality of general product-of-exponentials values is polynomial-time decidable by an iterative method;
- numeric inequality is much subtler and is tied to quantitative lower bounds for linear forms in logarithms;
- with a fixed number of terms, known bounds give unconditional polynomial time;
- for unbounded term count, their stated polynomial-time result depends on strong number-theoretic conjectures.

For a *canonical* prime vector, equality is easier still: compare coordinates. Numeric order remains the sign of

```text
sum_p (e_p - f_p) * log(p).
```

Adaptive interval logs can resolve most comparisons, but near-equal products may demand high precision. Reconstructing and comparing is polynomial in the expanded bit length, which may be exponential in the compact input length if exponents themselves are binary and huge. Complexity claims must state whether cost is measured in compact representation size or expanded value size.

Once arbitrary `+` and `-` gates are admitted, the relevant object is an arithmetic straight-line program. PosSLP asks whether the integer output of such a circuit is positive. Allender, Bürgisser, Kjeldgaard-Pedersen, and Miltersen place PosSLP in the counting hierarchy and show its centrality to numerical-computation complexity [S6]. This does **not** prove that a small Build 000 DAG will be intractable; it does show that “just retain an exact expression DAG and compare later” is not a free general solution.

Power circuits are a useful control example: carefully restricted base-2 exponentiation circuits can represent enormous exact integers and support several operations and comparisons in polynomial time, while unrestricted multiplication can cause exponential growth [S7]. Representation-specific normal forms can rescue a carefully chosen workload, but no single succinct form makes every operation cheap.

### 2.4 Fixed factor bases, smooth numbers, and S-units — closest bounded-lane model

Factoring algorithms routinely choose a finite factor base and record exponent vectors for values that are smooth over it. This is already a practical use of dense or sparse prime lanes; the number-field sieve literature is a canonical source [S8]. It works because the algorithm selects/filters its workload rather than representing every arbitrary integer in that basis.

For a fixed finite prime set `S`, positive `S`-smooth integers are closed under multiplication, gcd, and lcm, but not under addition. Allowing negative exponents gives the group of rational `S`-units. The deep literature on `S`-unit equations is a mathematical signal that additive relations inside a fixed multiplicative basis are exceptional, not an overlooked local rule [S9].

This makes a finite basis plus opaque cofactor one of the most honest architectures:

```text
value = sign * product_{p in B} p^e_p * cofactor
gcd(cofactor, product(B)) = 1
```

It preserves exact small-prime valuations without pretending the cofactor is prime or fully known.

### 2.5 Fermi–Dirac factorization — direct bridge from exponent counts to bits

Every exponent `e_p` can be expanded in binary. Therefore every positive integer has a unique squarefree product of factors `p^(2^k)` selected by the set bits of `e_p`. These are often called “Fermi–Dirac primes” in OEIS terminology [S10]. A useful address is `(prime_id, exponent_bit_index)`.

This is not a new algebra. It is the prime-exponent vector with each exponent stored in binary. Multiplying two values is binary addition of the exponent bit strings independently for each prime, including carries. It is nevertheless a valuable circuit baseline because it makes the hidden cost explicit:

```text
ordinary binary integer: carries run across place values of magnitude
Fermi–Dirac form: carries run within the exponent bits of each prime lane
```

A dense one-dimensional bitstring ordered by the numerical values of all `p^(2^k)` is generally wasteful; use sparse two-dimensional addressing. This representation should be tested as an explanatory control and is likely not a general performance win.

### 2.6 Logarithmic number systems — closest operation asymmetry in real hardware

Logarithmic number systems (LNS) store sign plus a finite representation of `log |x|`. Mitchell's 1962 binary-log multiplication work [S11] and the signed logarithmic system of Swartzlander and Alexopoulos [S12] are primary precedents. Multiplication/division become addition/subtraction of logarithms. Addition requires a nonlinear correction such as

```text
log(x+y) = max(log x, log y) + log(1 + exp(-|log x-log y|)),
```

implemented with tables/interpolation/approximation; subtraction and near cancellation are worse. Lewis developed a long-word addition/subtraction architecture using reduced lookup structures [S13].

LNS is not exact prime factorization, but it is the clearest historical warning against declaring victory because multiplication becomes addition: decades of engineering show where the cost reappears. Zero and sign require special encoding, and finite LNS normally approximates values.

### 2.7 Multidimensional logarithmic and double-base systems — very close finite exponent-lane hardware

Multidimensional LNS represents a value (exactly for a limited set, approximately more generally) by several bases raised to exponent coordinates. The hardware literature explicitly performs multiplication with parallel small exponent adders, while addition/conversion requires tables or a return to another domain [S14]. This is close to a fixed small-prime vector such as `(e_2,e_3,e_5)`.

Double-base number systems (DBNS) are different but especially relevant to the proposed “sum of factor words” architecture. A DBNS integer is represented as a sum of signed or unsigned terms `2^a 3^b`. Dimitrov, Jullien, and Miller analyze sparse representations, geometric/index implementations, and normalization/conversion costs [S15]. DBNS is redundant and is not a canonical full prime factorization. It demonstrates, however, that a small multiplicative atom set plus an additive term list can be useful for selected DSP and exponentiation workloads.

### 2.8 Residue number systems — strongest number-theoretic control architecture

An RNS value is a tuple of residues modulo pairwise coprime moduli. Garner's 1959 paper emphasizes carry-free parallel addition, subtraction, and multiplication, along with difficult relative magnitude and division [S16]. RNS has three important roles in Build 000:

1. It disproves any broad claim that “number-theoretic coordinates naturally privilege multiplication but disrupt addition.” Residue coordinates make both addition and multiplication local.
2. It provides a bit-efficient bounded-range comparator. If `M=product m_i`, the total residue storage is approximately `log2 M`, close to the information minimum.
3. It suggests a sidecar domain: factor coordinates for multiplicative structure plus residues for fast modular/additive projections.

Prime moduli do not make RNS prime-exponent representation. Its coordinates are remainders, not valuations. Conversion, sign/order, overflow, and extension of dynamic range are global operations.

### 2.9 Gödel-style prime-power coding — exact sequence encoding, loose arithmetic analogy

Gödel-style arithmetization encodes a finite sequence by assigning successive primes to positions and sequence entries to exponents [S17]. This is very close as a *data representation*. It is not evidence that the resulting integer should be the machine's arithmetic value. The factors are known by construction; evaluating the code may be enormous; concatenation/reindexing is not ordinary integer addition; and factoring a code received only as magnitude recreates the ingress problem.

Use this prior art to separate “prime coordinates are good structured storage” from “prime coordinates are a good general numeric ALU.” Gödel's original paper is the provenance source [S18]; the modern prime-power sequence presentation is documented clearly by the Stanford Encyclopedia supplement [S17].

### 2.10 Matula numbers and recursive prime indexing — the recursive path already encodes trees

Matula's 1968 correspondence recursively maps rooted trees to positive integers using prime factorization and the `n`th-prime function [S19]. It is adjacent to any proposal to represent prime IDs recursively by factorizing their indices.

The lesson is adversarial: recursive prime indexing naturally becomes a tree encoding. It can be mathematically elegant and bijective without making conventional arithmetic local. It also makes the `n`th-prime map, hence an ordered prime enumeration, a primitive operation. Treat it as a representation experiment or visualization, not as evidence of a lower physical arithmetic foundation.

### 2.11 Dataflow machines — useful execution substrate, loose numeric prior art

Dennis and Misunas's dataflow processor executes graph nodes when operand tokens arrive [S20]. Prime factors could be tagged tokens; independent prime lanes could merge/cancel in parallel; lazy arithmetic expressions are naturally dataflow graphs.

Dataflow changes scheduling and exposes parallelism. It does not remove the representation costs of prime identity, exponent addition, factorization, numeric order, or additive normalization. It is relevant to implementation architecture, not evidence for the mathematical representation.

### 2.12 Reversible computation — important invariant discipline, orthogonal to prime coordinates

Landauer connects logically irreversible operations with physical dissipation [S21]; Bennett shows how a general computation can be embedded reversibly by retaining history/intermediate results [S22]; Fredkin and Toffoli develop conservative reversible logic [S23].

A factor-domain operation can be made reversible in the same way as ordinary arithmetic:

```text
(x,y) -> (x, x+y)        # reversible over signed exponent vectors
(x,y) -> x+y             # not reversible; operand partition is lost
```

`COMPOSE(a,b)->c` discards which factors came from which input unless the inputs/history remain. Truncating negative exponents in a “cancel” operation is also lossy. Prime representation provides no exemption from reversible-computing constraints, though coordinate-local reversible adders may be a clean circuit experiment.

## 3. Adversarial cost analysis

### 3.1 Information-theoretic floor

Any injective fixed-width representation of the `N` integers in `[0,N-1]` needs at least `ceil(log2 N)` bits. For prefix-free variable-length codes, the uniform average length has the same logarithmic lower bound. Prime coordinates can compress selected structured values but cannot uniformly compress all integers without expanding others or charging an external dictionary.

Examples that do **not** contradict the bound:

- `2^e` can be stored as `(prime_id=2, exponent=e)` in `O(log e)=O(log log n)` bits. It is a highly structured member of the range.
- A prime near `N` needs an identity among `pi(N)` candidates. By the prime number theorem, an index still needs

  ```text
  log2 pi(N) = log2 N - log2 log N + O(1)
  ```

  bits, before decoding/table costs.
- An arbitrary `k`-element support among `m` basis primes needs at least `log2 binomial(m,k)` bits just to choose the support.
- A dense vector through the largest possible prime factor has about `pi(N)` lanes for values up to `N`, catastrophically larger than `log N` when `N` is large. A general implementation must be sparse or bounded-basis.

All benchmark reports should separate **representation bytes** from external prime-table bytes, allocator metadata, indexes, and caches.

### 3.2 Prime identity/index is not free

There are at least four implementable choices, with different costs:

| Prime identity scheme | Benefit | Hidden cost |
|---|---|---|
| store prime value | immediate reconstruction/modular use | about `log p` bits per large factor |
| store increasing prime index | saves roughly `log log p` bits for a large prime | `nth_prime`/table lookup and the conventional magnitude order are imported |
| fixed small-prime lane number | tiny IDs and SIMD-friendly | only a bounded smooth subdomain is native |
| interned dynamic atom ID | compact during one run | table persistence, primality certificate/provenance, canonical cross-run identity |

A residual composite must never be silently interned as a “prime atom.” Either prove/certify primality, mark it `OPAQUE_COFACTOR`, or allow a noncanonical product-of-exponentials representation.

### 3.3 Exponents reintroduce conventional arithmetic

The proposal moves multiplication of magnitudes into addition of multiplicities. It does not eliminate addition.

- Unary multiplicity: composition is token concatenation, but `p^e` takes `e` tokens and can require `Theta(log n)` space even for a single prime.
- Binary exponent counter: compact, but composition needs an adder for each matching prime lane.
- Fermi–Dirac occupancy: exposes the same counter as bits and carries.
- Recursively factorized exponent: terminates for finite values but requires prime indexing and still needs an operation corresponding to exponent addition. Matula-style trees show what this recursion represents structurally.

Build 000 should count exponent-adder gates/bit operations, not call coordinate merge “constant time.”

### 3.4 Ingress factorization is a real crossing cost

Converting arbitrary binary magnitude to a complete canonical prime vector is integer factorization. There is no known classical polynomial-time algorithm, but there is also no proven classical superpolynomial lower bound; describe the status as open, not as a theorem of hardness. Lenstra's ECM and the number-field sieve literature are representative classical algorithms [S8, S24]. Shor gives polynomial-time factoring on an ideal fault-tolerant quantum computer [S25], which changes the substrate and does not make classical ingress free.

The important workload distinction is:

- **constructed structural values**: if a value is born from known prime atoms and `COMPOSE`, no factorization is required;
- **arbitrary imported magnitudes**: complete canonical ingress may dominate every later saving;
- **partially known values**: retain a certified factor map plus opaque cofactor.

Benchmarks that pre-factor inputs off the clock must label that fact explicitly.

### 3.5 Addition and subtraction

For fully factored `a` and `b`, the minimum coordinate vector can be extracted, but the residual `a/g + b/g` can have unrelated large prime factors. Even `n` and `n+1` are coprime. Repeated increment therefore destroys almost all cached factor support at every step.

There is an obvious correct algorithm:

```text
reconstruct -> binary add/subtract -> factor result
```

but that is a domain crossing plus factorization. A lazy expression DAG avoids immediate factoring but shifts cost to equality, comparison, normalization, memory growth, and eventual evaluation.

Important honesty boundary: this survey did not establish an unconditional reduction proving that “factorized addition” (input factorizations, output factorization) is equivalent to factoring an arbitrary binary integer. Do not state such a hardness theorem without a citation. What is established here is the lack of a coordinate-local law, the exact valuation lower bound, and the practical need to discover new output factors.

Useful special cases do exist:

- common-factor extraction;
- unequal `p`-valuations, where the output `p`-valuation is known exactly;
- addition where one operand is zero;
- carefully bounded smooth domains and precomputed tables;
- retained p-adic unit/residue digits for selected primes;
- expression-DAG results that are not forced back into canonical factor form.

### 3.6 Equality, divisibility, and numeric comparison are different predicates

- Canonical equality: sparse-map equality; cheap.
- Divisibility: coordinatewise comparison; cheap.
- gcd/lcm: coordinatewise min/max; cheap.
- Numeric order: a weighted global comparison using `log p`, or reconstruction; not coordinatewise.
- Sign: a separate unit tag; not derivable from positive factor coordinates.

An adaptive exact comparator can:

1. cancel common coordinates;
2. accumulate certified intervals for `sum e_p log p` at increasing precision;
3. return when intervals separate;
4. fall back to exact big-integer reconstruction if the expanded bit length is acceptable.

Record how often and at what precision the fallback occurs. PoE comparison [S5] is the right theoretical warning for very succinct inputs.

### 3.7 Finite basis and closure

A physical machine has finite storage, so any dense prime bank is bounded. For basis `B`:

- `B`-smooth values are closed under multiplication and exact division within the domain;
- addition commonly exits the domain;
- a dynamic “new prime lane” requires discovery, identity allocation, and perhaps primality proof;
- an opaque cofactor preserves exactness but means some gcd/equality questions are no longer coordinate-local unless cofactors are compared/evaluated;
- fixed basis plus residues can answer selected valuation/modular questions without claiming full factorization.

The correct outcome type for an operation may be a tagged union such as `Smooth`, `PartialFactor`, `Magnitude`, or `Expr`, not a forced `FactorWord`.

### 3.8 Reconstruction and output lower bounds

Reconstructing `n` requires producing `L=floor(log2 n)+1` output bits. Any implementation that materializes ordinary magnitude has an `Omega(L)` bit-output cost regardless of how short the structural input is. Exponentiation by squaring and product trees can reduce arithmetic work, but cannot beat output size.

Similarly, printing decimal digits, indexing ordinary memory, comparing against a binary address, or talking to conventional I/O may force reconstruction. A factor-domain speedup is most plausible when values remain structural for many operations before crossing.

### 3.9 Memory locality and parallelism

Sparse sorted maps offer deterministic merging and canonical iteration but pointer-heavy implementations can have poor locality. Hash maps offer expected lookup but unstable order and substantial metadata. Packed dense lanes are excellent for a small basis and poor beyond it. A structure-of-arrays layout (`prime_ids[]`, `exponents[]`) and small-vector optimization deserve direct comparison.

Prime lanes are parallel in `COMPOSE`, `GCD`, `LCM`, divisibility, and valuation projection. The merge/frontier and memory allocation are not automatically parallel. In hardware, exponent width, support routing, and dynamic lane allocation may dominate the tiny lane arithmetic.

### 3.10 Reversibility and information loss

An exact factor vector loses no information about a nonzero positive integer. Projections and caches may:

- bounded-basis projection loses the unfactored part unless it is retained;
- approximate log magnitude loses exact equality information;
- `max(e_a-e_b,0)` loses whether/how far division failed;
- merging two operands into one result loses operand provenance;
- canonicalization may deliberately erase expression history.

Reversible experiments must retain inputs, quotients/remainders, or history/ancilla and count cleanup, just as in ordinary reversible arithmetic [S21-S23].

## 4. Candidate representations worth implementing

### Candidate A — exact sparse `FactorWord`

```text
FactorWord =
  Zero
  | NonZero {
      sign: +/-1,
      factors: sorted unique [(PrimeIdentity, NonZeroExponent)]
    }
```

For rational mode, exponents are signed. Prime identity should initially store the explicit prime value so that table costs are visible; an indexed variant can be benchmarked separately.

Core invariants:

- keys are certified prime and strictly increasing;
- zero exponents are absent;
- `Zero` has no factor payload;
- reconstruction is exact;
- rational and integer modes are distinct types or checked states;
- no opaque cofactor is mislabeled prime.

This is the baseline, not a novelty claim.

### Candidate B — bounded valuation bank plus exact cofactor

```text
BasisWord<B> = {
  zero/sign,
  exponent_lanes[p in B],
  cofactor_binary,
  invariant gcd(cofactor, product(B)) = 1
}
```

This avoids general factorization: strip a fixed small basis by division, keep the rest as magnitude. It gives deterministic ingress and lets Build 000 quantify whether cached small-prime valuations help factorial/combinatorial/rational workloads. Try bases sized to fit one cache line and SIMD register groups.

### Candidate C — Fermi–Dirac exponent-bit lanes

Represent each nonzero `e_p` as bits addressed by `(p,k)` for factor `p^(2^k)`. Implement compose as independent binary adders per prime. Compare gate/transition counts against:

- ordinary binary multiplication built from the same gate substrate;
- sparse integer-exponent merge;
- unary prime-token concatenation.

Likely value: explanatory and circuit-level evidence. Likely outcome: it relocates, rather than removes, carries.

### Candidate D — lazy factor-expression DAG

Nodes:

```text
AtomPrime(p) | Magnitude(n) | Product(children) | Sum(children)
| Neg(child) | Quotient(num,den)
```

Cache independently:

- known factor lower bound / common factor;
- exact magnitude if materialized;
- selected residues;
- certified log interval;
- zero/sign if established.

`Product` can normalize factor children cheaply. `Sum` first extracts common factors and remains opaque. The purpose is to test whether real workloads can postpone hard crossings long enough to win, not to promise a canonical new integer form. Cap DAG growth and measure sharing.

### Candidate E — dual factor/RNS sidecar

For a finite dynamic range, retain both factor information (when known) and residues modulo a fixed coprime set. Factor-to-residue projection uses modular exponentiation and is parallel. Residue addition is local; recovering a factor vector after addition is still not local. This candidate is valuable as a control showing that alternative coordinates can favor different operation sets.

### Candidate F — p-adic residue/valuation lanes for selected primes

For each small selected `p`, store `v_p(n)` and several p-adic unit digits/residues. This can determine more about `v_p(a+b)` in equal-valuation cases than exponent alone. It will not reconstruct arbitrary exact magnitude unless enough global information is carried. Treat it as an operation cache/sidecar, not the sole value representation.

### Candidate G — DBNS-style sum of smooth monomials

Represent an integer as a sparse signed sum of terms from a small basis, initially `2^a 3^b`. This is established DBNS territory [S15], so the research question is comparative: does a common gate/dataflow substrate expose a meaningful branch between canonical factor words and sparse sums of factor words? Track redundancy and normalization difficulty.

## 5. Candidate primitive operations

These names are implementation suggestions, not asserted natural laws.

### Native structural operations

```text
ATOM(p)             construct a certified prime atom
COMPOSE(a,b)        multiply; merge supports and add exponents
POWER(a,k)          scale exponent vector
QUOTIENT_EXACT(a,b) subtract exponents or fail with witness coordinate
GCD(a,b)            coordinatewise min
LCM(a,b)            coordinatewise max
DIVIDES(a,b)        coordinatewise <=
VALUATION(a,p)      read one coordinate
PROJECT(a,B)        split selected factors from residual
UNIT_PART(a,p)      strip selected p-power
```

### Explicit crossing operations

```text
INGRESS_FACTOR(n)   magnitude -> complete factor word; meter factorization
INGRESS_BASIS(n,B)  magnitude -> bounded valuation bank + cofactor
RECONSTRUCT(a)      factor/expression -> ordinary magnitude
TO_RESIDUES(a,R)    factor/magnitude -> residue bank
COMPARE_NUM(a,b)    adaptive logs/reconstruction, not coordinate order
ADD_SPLIT(a,b)      return known common factor plus residual sum expression
NORMALIZE(expr)     explicitly pay evaluation/factorization/circuit cost
```

Avoid an instruction named `DECOMPOSE` if it silently means “factor an arbitrary imported integer”; its cost and possible incompletion should be visible in the result type and receipt.

## 6. Experiments that would distinguish substance from notation

1. **Same lower substrate.** Build binary adder/multiplier, unary multiset, sparse exponent merge, and Fermi–Dirac lanes from the same Boolean/gate simulator. Count gates, transitions, depth, state bits, and wire/routing assumptions.
2. **Separate ingress, steady state, egress.** Report factorization, native-operation, normalization, and reconstruction time independently.
3. **Separate workload distributions.** At minimum: uniform random magnitudes, primes, balanced semiprimes, prime powers, smooth values, factorial/binomial products, rational-cancellation chains, multiplicative DAGs, increment/counter loops, and mixed add/multiply kernels.
4. **Representation receipts.** Measure payload bytes, total allocated bytes, prime-table bytes, support count, exponent bit count, cache misses if available, and expanded magnitude bit length.
5. **Addition churn.** Measure retained support (`gcd` coordinates), new factors, factoring time, and DAG growth across random addition, `n+1`, shared-factor sums, and equal/unequal valuation cases.
6. **Comparison precision.** Implement certified log intervals and record precision iterations/fallback rate; include adversarial close products and consecutive smooth values.
7. **Bounded-basis sweep.** Vary basis size and quantify hit rate versus lane/storage cost. Never count an opaque cofactor as factored.
8. **Exhaustive correctness.** Exhaust small domains for every representation and operation; randomized differential tests against ordinary big integers beyond them.
9. **Formal reuse.** Reuse mathlib's established factorization theorems as the reference model if Lean work is useful; do not spend Build 000 reproving unique factorization merely to relabel it.
10. **Lazy-expression limits.** Compare eager reconstruction/factorization against DAG retention under explicit memory caps and canonicalization checkpoints.

## 7. Likely dead ends or claims to reject early

- A dense coordinate for every prime as a general unbounded integer representation.
- Treating `prime_index` as a cost-free physical primitive; the prime table/enumeration and conventional order are part of the machine.
- Saying multiplication is “just vector addition” without counting sparse merge, exponent adders, carries, routing, allocation, and normalization.
- Canonically refactoring after every ordinary addition, subtraction, increment, comparison, address calculation, or loop counter update.
- Using a high-level prime-number library over host big integers and claiming the computational floor was forked.
- Recursive factorization of prime indices/exponents as proof that ordinary magnitude is unnecessary; Matula-style encodings show that this builds a tree code unless additional arithmetic structure is supplied.
- Using Gödel coding as evidence of an arithmetic advantage; it is evidence of structured sequence encoding.
- Calling RNS prime-native because the moduli happen to be prime; residue and valuation coordinates are different.
- Treating logarithmic or MDLNS hardware wins as exact-integer wins without accounting for approximation, zero/sign, addition tables, and conversion.
- Assuming quantum or analog factorization machinery makes ordinary classical ingress free.
- Claiming universal compression from short encodings of powers or smooth numbers.
- Treating an opaque composite cofactor as a new prime atom, which destroys canonicality and honest divisibility semantics.
- Treating a sum/product DAG as a canonical integer without paying for semantic equality/order and controlling expression growth.
- Claiming factorized addition is proven equivalent to general factoring; that reduction was not established in this survey.

## 8. Most justified Build 001 direction if Build 000 confirms these expectations

The most defensible next direction is a workload-specific **multiplicative structural coprocessor / IR**, not a replacement general-purpose integer foundation. It would:

- keep exact prime structure when values are born structurally;
- expose gcd/lcm/divisibility/cancellation as first-class local operations;
- maintain bounded valuation and residue caches;
- allow lazy additive nodes with common-factor extraction;
- cross to binary magnitude explicitly when order, arbitrary addition, I/O, or addressing requires it;
- and produce receipts showing where factorization, reconstruction, and canonicalization costs occurred.

The genuinely interesting research question after removing the known mathematics is: **Can typed domain residence and delayed crossings yield reproducible wins on identifiable workloads, while a shared gate/state model shows exactly where the costs moved?**
